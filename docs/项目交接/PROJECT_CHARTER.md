# 个体化 BCI 流水线自主发现系统：项目宪章

> 版本：v0.2  
> 日期：2026-08-03  
> 当前阶段：GOAI AI for Research 开放探索赛初赛准备  
> 初赛提交截止：2026-08-16

## 1. 文档目的

本文档用于固定项目的核心问题、研究边界、系统目标和验证原则，防止开发过程中因追逐新模型、堆叠 Agent 或单纯优化准确率而偏离最初目标。

若后续设计与本文档冲突，应先说明为什么需要调整，再更新本文档；不应在没有记录的情况下悄然改变项目目标。

## 2. 一句话定义

给定一个新的脑机接口数据集、具体被试的校准数据、研究任务和计算预算，系统自动建立数据画像、检索领域知识、设计并执行候选分析流水线，为每位被试选择经过独立验证的个体化方案，并输出可复现、可审计、由实验支持的选择依据。

## 3. 项目愿景

当前脑机接口算法研究包含大量重复性工作：研究人员需要根据经验反复尝试预处理、频段、通道、时间窗、特征、分类器和超参数，复现多个基线，排查运行问题，再整理结果和解释方法选择。这些工作必要但机械，消耗了本可用于科学问题、实验范式、神经机制和真实应用的时间。

本项目希望构建一个可信的 AI 科研助手，自动完成其中可标准化、可计算、可验证的部分。系统不替代研究人员提出科学问题，也不替代领域专家判断结论的意义；它负责高效、透明地完成个体化流水线发现与验证。

## 4. 核心洞察

### 4.1 个体差异应成为建模对象

不同被试在以下方面可能存在差异：

- 神经振荡的峰值频率和能量分布；
- ERD/ERS 等任务相关响应的空间、频率和时间特征；
- 有效通道、空间滤波结构和协方差模式；
- 伪迹类型、信噪比和试次稳定性；
- 认知策略、注意、疲劳和执行一致性；
- 头部结构、电极位置、阻抗和采集环境。

因此，不应默认一条全局流水线适合所有被试。项目倾向于为每位被试选择不同的完整流水线，而不只是训练不同的模型参数。

需要保持严谨：项目可以研究个体信号与最优流水线之间的关系，但不能仅凭分类结果宣称不同个体具有某种特定的“思考方式”。

### 4.2 泛化的是科研方法，而不是单一解码器

本项目不以训练一个直接适用于所有被试、设备和数据集的万能模型为目标。

我们希望验证的是：面对一个此前未处理的数据集或被试，固定的 Agent 工作机制能否重新分析数据特点、检索经验、设计实验，并为当前对象找到合适方案。

```text
数据集 A -> 分析 A -> 为 A 的各被试生成个体化方案
数据集 B -> 分析 B -> 为 B 的各被试生成个体化方案
数据集 C -> 分析 C -> 为 C 的各被试生成个体化方案
```

跨数据集评价的是 Agent 的任务级适应能力，而不是数据集 A 所训练分类器在数据集 B 上的直接性能。

### 4.3 “最优”必须有边界

项目不宣称寻找数学意义或无限搜索空间中的绝对最优方案。本文所称“个体最优”是指：

> 在预先定义的合法流水线空间、实验协议、数据边界、评价目标和计算预算下，找到经确认数据验证的最佳或 Pareto 优选方案。

最优标准不应只有准确率，还应考虑：

- 未见数据上的预测性能；
- 不同划分和随机种子下的稳定性；
- 训练和推理成本；
- 搜索所需实验次数；
- 数据保留比例与预处理可靠性；
- 模型复杂度；
- 结果可解释性和可复现性。

## 5. 核心研究问题

### 主问题

在固定实验预算下，基于数据画像与领域知识的 Agent 系统，能否比全局统一流水线、随机搜索和通用 AutoML，以更少的实验次数，为每位被试找到接近其个体 oracle 的完整 BCI 流水线，并生成忠实于数据和实验结果的解释？

### 初步研究假设

- **H1：个体化收益。** 个体化流水线在总体上优于所有被试共用的全局最佳流水线。
- **H2：搜索效率。** 数据画像和知识引导的 Agent 能以少于穷举搜索的实验次数，找到接近个体 oracle 的方案。
- **H3：验证有效性。** 搜索阶段与确认阶段隔离后，Agent 推荐方案仍能在未参与选择的数据上保持性能。
- **H4：解释忠实性。** Agent 给出的关键选择理由能够通过消融、反事实或重放实验获得支持，而非仅为事后生成的语言描述。

## 6. 系统输入与输出

### 输入

- 脑信号数据及必要的元数据；
- 被试、会话、试次和标签结构；
- 研究范式及任务目标；
- 允许使用的工具、算法和数据范围；
- 计算预算和停止条件；
- 评价指标及科学约束。

### 输出

- 数据集级约束和质量报告；
- 每位被试的数据画像；
- 候选流水线及提出理由；
- 完整实验轨迹、配置、日志和结果；
- 每位被试的最终推荐流水线；
- 搜索集与冻结确认集上的表现；
- 与全局流水线、随机搜索等基线的比较；
- 可复现的代码、环境和运行说明；
- 包含证据、适用边界和不确定性的个体化解释报告。

## 7. 建议系统架构

Agent 是逻辑职责，不要求每个职责都对应一个独立大模型进程。数值计算、数据校验和统计验证应尽可能由确定性程序负责，LLM 主要负责语义理解、知识整合、实验编排、失败诊断和报告组织。

### 7.1 数据集理解层

识别并验证：

- 信号模态、研究范式和标签语义；
- 采样率、通道、电极位置和记录设备；
- 被试、会话、事件和试次结构；
- 可用数据量和类别平衡；
- 合法的数据划分方法；
- 当前任务可使用的流水线组件。

### 7.2 被试画像层

使用确定性工具提取结构化元特征，例如：

- 信噪比、坏导和伪迹画像；
- 功率谱和个体峰值频率；
- 与任务相关的频段、通道和时间响应；
- 协方差结构和初步可分性；
- 试次稳定性和时间漂移；
- 样本量、类别平衡和数据质量。

LLM 不应直接凭肉眼“阅读”大规模原始 EEG 数组，而应基于可追溯的结构化数据画像推理。

### 7.3 知识与经验层

知识来源可包括：

- 经过筛选的论文与方法说明；
- 开源工具的官方文档；
- 历史数据集及被试的实验记录；
- 神经生理与统计规则；
- 流水线组件的兼容性和适用边界。

知识库不只存储“哪个算法分数高”，还应记录数据条件、评价协议、失败案例和适用限制。

### 7.4 候选流水线生成层

根据数据集约束和被试画像，从合法搜索空间中提出少量具有依据的候选方案。流水线可能包含：

- 数据质量处理和伪迹策略；
- 通道选择；
- 频段与时间窗；
- 特征提取与选择；
- 缩放和正则化；
- 分类器或轻量模型；
- 超参数；
- 评价协议。

比赛 MVP 应优先使用结构化配置或声明式流水线，而不是让 LLM 无约束生成任意代码。

### 7.5 预算化实验层

```text
提出候选 -> 执行 -> 分析结果 -> 更新信念
        -> 选择下一项最有价值的实验 -> 收敛或停止
```

顺序决策可以结合贝叶斯优化、多臂老虎机、候选组合排序或其他预算感知方法。系统价值在于减少无效实验，而不是把所有算法全部暴力跑完。

### 7.6 科学审计与确认层

系统应检查：

- 数据泄漏；
- 被试、会话和试次边界；
- 在数据划分前拟合预处理；
- 重复查看确认集；
- 不适当的评价指标；
- 不兼容或神经生理上不合理的组件；
- 随机种子和单次偶然结果；
- 证据不足时是否应拒绝给出确定结论。

每位被试的数据应尽可能分为：

- **搜索/校准数据：** Agent 可以反复实验；
- **冻结确认数据：** 最终流水线锁定后才允许评估。

如果数据不足，应使用严格的嵌套交叉验证或其他等价协议，并明确其限制。

### 7.7 证据报告层

最终报告应回答：

- 为什么推荐该流水线；
- 哪些数据特征支持该选择；
- 尝试和淘汰了哪些替代方案；
- 性能改善来自哪个环节；
- 结果是否稳定；
- 在什么条件下可能失效；
- 如何完整重放实验。

解释必须尽可能由数据、实验和消融支持，不能仅依赖 LLM 的自然语言合理化。

## 8. GOAI 比赛 MVP 边界

### 建议范围

- 第一版仅支持 EEG；
- 比赛 MVP 正式锁定运动想象（Motor Imagery, MI）解码；
- 项目发起者具有运动想象 EEG 数据采集、预处理和分析的完整流程经验；
- 使用公开且授权清晰的数据；
- 选择 1–2 个数据集；
- 建立一个受约束的小型流水线候选库；
- 展示至少 2–3 位具有明显差异的被试；
- 跑通数据画像、候选生成、实验执行、最终选择、冻结验证和解释报告的闭环；
- 对比全局统一流水线与个体化方案。

### 暂定目标指标

以下是开发目标，不是尚未验证的成果声明：

- 相比穷举减少至少 50% 的候选实验；
- 在预定义搜索空间内，与个体 oracle 的性能差距控制在约 2–3 个百分点；
- 总体优于所有被试共用的全局流水线；
- 不同被试能够获得不同的合理方案；
- 推荐理由至少有数据特征或消融实验支持；
- 实验配置、日志和结果可以完整重放。

### 初赛阶段的优先级

1. 科学问题成立且范围清晰；
2. 与现有工作的差异明确；
3. 评价框架可信；
4. 最小闭环具有实现可行性；
5. 展示初步证据或原型；
6. 再考虑界面美观和功能扩展。

## 9. 明确不做什么

为防止范围失控，比赛 MVP 暂不做：

- 同时完整支持 EEG、MEG、fNIRS 等多种模态；
- 训练一个适用于所有被试和设备的万能解码模型；
- 搜索无限或无约束的任意 Python 程序；
- 以刷新单一数据集最高准确率为核心目标；
- 仅用一个漂亮的聊天界面替代真实实验执行；
- 用多个 Agent 的数量充当技术创新；
- 在没有独立证据的情况下宣称发现神经机制；
- 在证据不足时强行输出“最佳方案”；
- 使用未经导师或权利人确认可公开的实验室数据、代码或未公开成果。

## 10. 与现有工作的定位差异

- 相比固定自动预处理工具：本项目根据数据和被试特点选择完整方案。
- 相比 EEG AutoML：本项目加入领域知识、科学审计、实验编排和证据报告。
- 相比个体化分类器选择：本项目选择的是包含预处理、特征、模型和验证协议的完整流水线。
- 相比 NeuroWeaver 类代码搜索 Agent：本项目强调被试级个体化、受约束搜索、搜索/确认隔离和解释忠实性。
- 相比 EEGAgent/BrainAgent 类工具编排系统：本项目关注自主实验选择与个体化流水线发现，而不只是完成用户指定的分析。
- 相比 CogEEGAgent 类科学验证系统：本项目把选择感知的验证机制用于 BCI 解码流水线搜索，而不局限于封闭的 ERP 分析模板。

## 11. 项目成功标准

### 比赛成功

- 问题定义清晰、真实且有文献依据；
- Demo 跑通至少一个完整场景；
- 能直观展示不同被试获得不同流水线；
- 有可信对比、日志和验证证据；
- 代码和文档具备基本开源复用价值。

### 科研成功

- 个体化收益在多个数据集上具有统计支持；
- Agent 在固定预算下优于随机搜索或通用 AutoML；
- 搜索结果能够在冻结确认数据上复现；
- 解释通过消融或反事实验证；
- 研究协议、代码和实验记录可以由第三方重放；
- 清楚报告负结果、失败被试和方法适用边界。

### 实际价值成功

- 显著减少研究人员配置、执行和整理基线实验的时间；
- 失败时能够给出可诊断信息，而非静默输出错误结果；
- 研究人员能够理解、修改和批准系统的关键决策；
- 系统产出可以直接进入后续科研工作流。

## 12. 主要风险与防偏原则

| 风险 | 防偏原则 |
|---|---|
| 变成纯准确率搜索 | 始终同时报告确认性能、稳定性、成本和证据 |
| 变成普通 AutoML | 强调数据理解、知识约束、顺序实验、审计和解释 |
| 为了展示堆很多 Agent | Agent 数量服从职责需要，不作为卖点 |
| 搜索空间过大导致无法完成 | 先用受约束候选库完成闭环，再逐步扩展 |
| 解释只是事后合理化 | 用消融、反事实和实验重放验证关键解释 |
| 数据泄漏造成虚高结果 | 冻结确认数据；所有数据依赖操作只在训练侧拟合 |
| 使用单一被试成功案例 | 同时展示成功、普通和失败被试 |
| 对外宣称过度 | 区分目标、初步结果和已验证结论 |
| 与最新论文高度重合 | 持续维护相关工作矩阵，明确新增贡献 |
| 竞赛公开影响论文或知识产权 | 提交前与导师确认数据、代码、作者和公开边界 |

## 13. 赛后论文路线

比赛 MVP 完成后，可在导师指导下扩展：

1. 正式定义“固定预算下的个体化 BCI 全流水线发现”任务；
2. 扩展多个公开数据集和更多被试；
3. 扩展预处理、通道、频段、特征和模型搜索空间；
4. 构建严格的数据生命周期和冻结确认协议；
5. 与全局流水线、随机搜索、贝叶斯优化、传统 AutoML 和相关 Agent 系统比较；
6. 完成数据画像、知识库、搜索策略、审计模块和解释模块的消融；
7. 研究被试元特征与流水线选择之间的可解释关系；
8. 发布可复现基准、代码和完整实验轨迹；
9. 在此基础上再考虑 P300、SSVEP、情绪等范式以及 MEG/fNIRS 扩展。

## 15. 项目决策准则

后续每增加一个功能，应回答：

1. 它是否直接帮助个体化流水线发现？
2. 它是否提高搜索效率、科学有效性或解释可信度？
3. 它是否能在比赛时间内得到验证？
4. 如果删除它，核心闭环是否仍然成立？

若前三问多数为“否”，或该功能不影响核心闭环，应推迟到赛后。

## 当前共识摘要

我们要做的不是万能脑电模型，不是批量跑分工具，也不是以聊天界面包装的 EEG 分析脚本。我们要验证的是：一个受领域知识和科学规则约束的 Agent 系统，能否理解每位被试的数据特点，以较少实验找到适合该被试的完整 BCI 流水线，并用独立验证和可重放证据解释自己的选择。
